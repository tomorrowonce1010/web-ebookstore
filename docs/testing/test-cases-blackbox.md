## 2. 当前黑盒自动化口径

本仓库当前黑盒自动化只保留：

- `Playwright` 浏览器端到端黑盒测试

不再保留以下黑盒执行层：

- 后端 API 级黑盒测试
- 前端页面级黑盒测试

这样做的目的，是让黑盒测试执行口径统一为“真实浏览器 + 真实前端页面 + 真实后端接口 + 当前数据库环境”的外部行为验证。

## 8. 当前已由 Playwright 覆盖的黑盒场景

### 8.1 决策表场景

- 未登录访问购物车时重定向到登录页
- 用户名正确但密码错误时登录失败
- 普通用户访问管理员订单页时显示权限不足
- 管理员登录后访问订单管理页
- 管理员访问图书管理页
- 管理员发起图书销量统计查询
- 管理员切换到用户消费统计并查询
- 普通用户查询个人购书统计

### 8.2 边界值场景

- 注册用户名长度小于 3 时被前端校验拦截
- 注册确认密码不一致时被前端校验拦截
- 购物车有商品但未勾选任何商品时，结算按钮禁用

### 8.3 等价类与核心成功链路场景

- 搜索不存在的图书关键字时显示空结果提示
- 普通用户登录成功
- 浏览图书列表
- 进入图书详情页
- 将图书加入购物车
- 勾选商品后成功结算
- 订单页按书名查询订单

说明：核心成功链路在一个 Playwright 用例中连续覆盖了“登录 -> 浏览 -> 详情 -> 加购 -> 结算 -> 查单”多个黑盒测试点，因此端到端黑盒测试中“覆盖内容数量”大于“测试用例数量”是正常现象。

## 9. Playwright 与黑盒设计方法的关系

Playwright 不是新的黑盒设计方法，而是黑盒设计方法的执行载体：

- 等价类：决定选取哪些代表性输入
- 边界值：决定哪些临界点必须单独验证
- 决策表：决定多条件组合下系统应出现什么行为
- Playwright：把这些高价值黑盒场景放到真实浏览器里自动执行

因此，当前 Playwright 用例依然是标准黑盒测试，而且更接近真实用户的实际使用方式。
