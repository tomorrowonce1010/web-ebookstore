# 《大模型驱动的智能化软件测试》测试计划

## 1. 文档信息

- 被测项目：在线书店系统
- 需求依据：`README.md`
- 大模型 Agent：`Codex`
- 测试目标：构建一套由 Codex 驱动的可执行、可复现的软件测试工作流，覆盖黑盒与白盒两部分

## 2. 测试目标

1. 从需求文档中提取不少于 10 个功能点并形成测试范围
2. 使用 Codex 辅助完成测试计划、测试用例、测试代码、测试报告
3. 黑盒测试覆盖等价类、边界值、决策表
4. 白盒测试覆盖代码覆盖、基本路径覆盖、数据流分析
5. 验证在线书店系统的核心业务闭环和后台管理能力

## 3. 被测对象范围

### 3.1 前端

- React 页面
- React Router 路由与权限控制
- Ant Design 交互页面
- fetch API 调用链路

### 3.2 后端

- Spring Boot Controller
- Service 业务逻辑
- DAO/Repository 数据访问
- Session 与权限拦截逻辑

## 6. 测试方法

### 6.1 黑盒测试

黑盒测试完全统一为 Playwright 浏览器端到端自动化执行。

设计方法包括：

- 等价类
- 边界值
- 决策表

黑盒执行方式：

- 前端和后端启动后，执行 Playwright 浏览器端到端测试

### 6.2 白盒测试

白盒测试保持现有实现，不在本轮黑盒调整中改动。

设计方法包括：

- 代码覆盖
- 基本路径覆盖
- 数据流分析

## 10. 风险与关注点

1. 数据库当前没有统一一键重置脚本，黑盒自动化优先覆盖稳定可复现的高价值场景
2. 浏览器端到端测试会暴露真实联调问题，例如地址、CORS、前端定位器和页面结构问题
3. 前后端服务必须稳定运行在 `localhost:3000` 和 `localhost:8081`
